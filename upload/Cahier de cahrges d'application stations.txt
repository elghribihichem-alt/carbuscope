Cahier de cahrges d'application " waze de carburant"

Plateforme "Waze du Carburant" — Observatoire Web B2B + Application Mobile B2C + Portail Enseigne
Version 2.0 — Document de référence fonctionnelle, technique et économique
Périmètre : Tunisie, avec projection Maghreb à horizon 5 ans

PARTIE 1 — CONTEXTE, VISION ET POSITIONNEMENT
1.1 Contexte
Le marché tunisien des stations-service compte 1 814 stations réparties sur l'ensemble du territoire. Les principaux opérateurs sont Agil (228), TotalEnergies (151), Staroil (120), Shell, Ola et une majorité d'indépendants. Le parc automobile a atteint 93 095 immatriculations en 2025 (+17,3 % vs 2024), contre 55 000 en 2015. Le réseau autoroutier s'étend sur 743 km avec un objectif de 1 320 km d'ici 2035.

Malgré cette dynamique, aucun outil unifié ne permet :

Aux automobilistes de trouver une station selon leurs besoins réels (services, horaires, disponibilité)

Aux enseignes de piloter leur réseau avec une intelligence concurrentielle

Aux stations de gagner en visibilité terrain

Aux sponsors d'atteindre une audience captive qualifiée

1.2 Vision
Construire l'infrastructure de données de référence du secteur des stations-service en Tunisie, articulée autour de trois couches auto-alimentées :

Couche	Acteur	Apport	Bénéfice
1	Utilisateurs	Avis, signalements, photos	Utilité, reconnaissance
2	Enseignes	Données officielles de leurs stations	Visibilité, image, contrôle
3	Plateforme	Trafic, parc auto, démographie, projets	Légitimité, autorité, valeur ajoutée
1.3 Positionnement
"Le Waze du carburant" — mais un Waze qui ne se contente pas de guider : il certifie la donnée, analyse le marché et éclaire les décisions stratégiques.

Trois produits, une seule base de données :

Application Mobile (B2C) : pour les automobilistes

Observatoire Web (B2B) : pour les directions d'enseignes

Portail Enseigne (B2B2B) : pour l'auto-publication des données

PARTIE 3 — MODÈLE DE DONNÉES ET GOUVERNANCE
3.1 Les trois couches de données
Couche 1 — Contributions utilisateurs
Type	Poids	Validation
Signalement isolé	Faible	À vérifier
3 signalements concordants	Moyen	Alerte
Confirmation par agent	Fort	Certitude
Confirmation par enseigne	Fort	Certitude
Règles :

Un signalement isolé ne modifie jamais la base automatiquement

Un utilisateur avec historique fiable a un poids plus fort

Un utilisateur nouveau ou suspect a un poids faible

Les signalements sont horodatés et géolocalisés

Couche 2 — Données enseignes
Type	Visibilité	Validation
Localisation, services, horaires	Publique	Légère
Photos officielles	Publique	Légère
Promotions	Publique	Légère
Fréquentation, incidents	Privée	Aucune (déclaratif)
Règles :

Une enseigne ne peut modifier que ses propres stations

Les modifications sont tracées (auteur, date, IP)

Les utilisateurs peuvent contester

La plateforme arbitre

Couche 3 — Données plateforme
Type	Source	Fréquence
Trafic routier	Tunisie Autoroutes, Ministère Équipement	Annuelle
Parc automobile	INS, ATTT	Semestrielle
Démographie	INS	Annuelle
Projets d'infrastructure	Ministère Équipement	Trimestrielle
Réglementation	Ministère Énergie	Trimestrielle
Règles :

Chaque donnée a une source, une date, une méthode

La méthodologie est documentée et publique

Les données sont versionnées

3.2 Indicateurs de fraîcheur
Indicateur	Définition	Cible
Taux de fraîcheur	% fiches vérifiées < 12 mois	> 90 %
Taux de précision	% fiches exactes (audit aléatoire)	> 95 %
Délai de détection	Temps entre changement et détection	< 30 jours
Délai de mise à jour	Temps entre détection et MAJ	< 7 jours
Taux de couverture	% stations existantes présentes	> 95 %
Taux de signalement	Signalements utilisateurs/mois	Croissant
3.3 Cycle de vie d'une fiche
Création : première saisie, source, date

Validation initiale : terrain ou enseigne

Mise en service : publication, compteur de fraîcheur

Signal : événement détecté

Re vérification : agent confirme ou infirme

Mise à jour : modification tracée

Archivage : fermeture documentée

Règle d'or : on ne supprime jamais une fiche. On l'archive avec date et source.
